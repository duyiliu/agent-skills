# AI 通用测试检查点（Web 管理系统）

> 正本位置：本仓库 `skills/engineering/ai-test-checkpoints`。
> 来源：对某真实管理系统 133 条历史缺陷的模式反向归纳，并经 design-handoff 社区高频问题清单（UXPin/Miro/Storyflow 等，2026-10）对照补充。
> 核对日期：2026-10-02。适用范围：跨项目的 Web 管理系统（表单/列表/详情类页面）。可信度：高（每条检查点对应一类反复出现的真实缺陷模式）。
> 用法：与具体项目解耦——项目特定口径（排序键、状态机、范围定义、脱敏策略）从当前项目的适配文档或需求方补充，本清单只提供通用判定标准。

---

## 使用说明

1. **按页面类型选维度**：表单页 → 一、二、三、六、七、八；列表页 → 四、五、七；详情长页 → 九；全部页面 → 十一、十二。
2. **先枚举后执行**：先完整列出页面全部字段（含折叠/联动隐藏区）、按钮、筛选/tab/排序控件、敏感字段，再逐条执行检查点。枚举不完整 = 检查不完整。
3. **三态输出**：每条检查点记录 通过 / 不通过 / 不适用（附原因）。不通过必须附证据：截图或 DOM 片段、接口请求/响应报文（可得时）、复现步骤。
4. **缺项申报机制**：被测行为在需求文档中缺失或含糊、且本清单的通用规则也无法判定时——不臆测、不判不通过、也不放过，输出到报告的"待确认清单"，转需求方拍板。
5. **严重度分级**：P0 = 脏数据落库 / 数据丢失 / 校验绕过 / 串单提交 / 敏感信息泄露；P1 = 功能不可用 / 口径错误 / 计算错误；P2 = 交互缺失（无提示、无禁用、不刷新、无拦截）；P3 = 界面还原偏差。
6. **报告格式**：结论行（通过 / N 个问题，按级别计数）+ 问题表（编号、维度、检查点、级别、现象、复现步骤、证据）+ 待确认清单 + 未覆盖项。

7. **高频典型优先**：在「原型直接转开发」（无独立需求文档）的项目上，以下五类覆盖约 85% 的历史缺陷，优先执行——①字段校验规则；②分版本表单逐版本还原；③联动与动态行为；④列表口径（排序/筛选/统计/范围）；⑤状态流转与操作反馈（含离开保护）。

---

## 高频典型与原型增补要求

**根因链**：原型只承载「视觉 + 结构」两类信息；「行为 + 规则」两类信息在直接转开发时整体丢失，形成五类高频缺陷：

| 典型 | 缺陷模式 | 对应维度 |
|---|---|---|
| 1 校验规则缺失 | 原型只画正常态不画错误态，必填/格式/值域/提示文案无人定义 | 一 |
| 2 分版本收敛过度 | 原型逐版本画全，开发合并为通用实现，版本差异（标题/文案/控件类型）被抹掉 | 十（J2） |
| 3 联动行为缺失 | 原型只画展开终态，不画触发条件、取消行为、切换清理 | 二 |
| 4 口径漂移 | 排序/筛选/统计/范围是纯业务规则，原型形式上无法表达，无人拍板则各写各的 | 四、五 |
| 5 单页视角 | 页面间时序与过程性交互（提示/禁用/离开确认/刷新）完全空白 | 五、七、八 |

**原型最小增补要求**：评审原型时要求补齐五样——①字段校验规则清单；②联动触发条件；③状态流转图；④异常与边界态（空/加载/错误/慢/溢出五态；社区经验：边界态缺失是建成后偏差的最大单一来源）；⑤标注硬约束与可权衡项（区分不可协商规则与可自行取舍的偏好，防止开发在工期压力下擅自简化）。补不出来的部分走缺项申报机制转需求方拍板，不留给开发脑补。

## 一、字段校验

### 1.1 字段类型通用规则（按字段类型自动套用，无需需求文档）

| 编号 | 字段类型 | 动作 | 判定标准 |
|---|---|---|---|
| A1-1 | 带校验位的编号类（证件号等） | 输入非法格式号、校验位错误的号 | 提示"格式无效"且保存禁用；合法值自动推导的关联字段（如出生日期、性别）正确回填 |
| A1-2 | 日期类 | 输入晚于当前日期、非法文本、超合理业务范围的值 | 晚于当前日期阻断并提示；非法文本提示"请输入有效日期"；超范围出弱警告（不阻断）；三种情况下保存均不可用 |
| A1-3 | 联系方式类 | 输入位数不足、非数字、非法号段的值 | 提示格式错误且保存禁用 |
| A1-4 | 数值测量类 | 输入负数、超出合理上下限的极端值、边界值 | 超界出软提示；极端值不得静默保存；边界值可正常保存；单位与精度正确 |
| A1-5 | 枚举/单选类 | 查看全部可选项 | 值域固定且完整；不得允许自由输入；不得写死不可改（业务锁定的须有提示） |
| A1-6 | 条件输入类（"其他"说明等） | 勾选/选择触发项 | 说明输入框自动聚焦且必填；取消触发项后说明框行为明确（清空或保留），不得悬空提交 |
| A1-7 | 长文本类 | 输入超长文本、特殊字符 | 长度软校验；特殊字符不破坏布局与保存 |

### 1.2 必填与提交控制

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| A2-1 | 必填拦截 | 将每个必填字段逐个清空后提交 | 前端拦截并给出明确提示文案 |
| A2-2 | 异常不裸抛 | 触发各类校验失败 | 不出现后端原始异常直接抛给用户（裸堆栈、裸错误码均算不通过） |
| A3-1 | 禁用态：必填为空 | 必填未填满时观察保存按钮 | 禁用 |
| A3-2 | 禁用态：无变更 | 表单无任何修改时观察保存按钮 | 禁用 |
| A3-3 | 禁用态：已完结对象 | 打开已完成/已归档的对象 | 相应保存/草稿类按钮禁用 |
| A3-4 | 禁用态：批量无选中 | 不选中任何行 | 批量操作按钮禁用 |

### 1.3 服务端兜底与数据真实性

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| A4-1 | 服务端兜底 | 绕过界面直接调保存接口：缺必填、超值域、非法枚举、类型错误 | 服务端必须拦截且返回友好业务文案；脏数据落库 = P0 |
| A4-2 | 落库核验 | 保存成功后查详情/存储 | 无空串冒充空值；枚举列只存值域内合法值 |
| A4-3 | 数据真实性 | 检查操作人、责任人、审计类字段 | 无上下文时必须为空，不得填 0、1、"system" 等伪造默认值 |

## 二、联动与自动推导

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| B1 | 展开/收起 | 勾选触发项，观察子表单区 | 子区出现、无多余高亮或错位；取消勾选后子区数据处理明确 |
| B2 | 切换清理 | 在互斥或关联选项间切换 | 切换后关联字段清空/保留行为一致；不得残留前一选项的值 |
| B3 | 互斥共存 | 同时勾选两个互斥选项 | 系统阻止或自动清空冲突项，不得共存提交 |
| B4 | 关联必填 | 选择"异常/有/是"类选项后直接保存 | 关联量化字段变必填；不填不得保存且不出系统异常页 |
| B5 | 自动计算回填 | 修改被推导的源字段 | 推导字段自动回填且计算正确 |
| B6 | 自动值可覆盖性 | 手动修改自动推导的值 | 允许修改（业务锁定的须有提示） |
| B7 | 编辑回显 | 保存后重新打开 | 所有字段完整回显，尤其"其他"文本、组合控件、联动隐藏区 |
| B8 | 动态过滤 | 逐个切换驱动条件（类别/状态/年龄段等） | 动态展示区域的过滤结果逐条件正确 |

## 三、多实例提交边界（P0 高危区）

> 适用：同一业务对象可同时存在多个可编辑实例的页面（多张单据、多个 tab、主子表单）。

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| C1 | 提交隔离 | 暂存实例 A 后提交实例 B | 仅 B 被提交，A 保持原状态 |
| C2 | 校验不被绕过 | 同上场景 | B 自身必填校验完整生效，不受 A 已暂存影响 |
| C3 | 状态互不影响 | 观察 A 的操作前后 B 的状态 | B 的可用性与数据不变 |
| C4 | 并发切换 | 编辑 A 中途打开 B 再返回 A | A 数据仍在且未误提交 |

> 方法：构造"A 已暂存 + B 待提交"场景，交换 A/B 顺序双向各跑一遍。

## 四、列表（排序/筛选/统计/刷新）

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| D1 | 排序正确性 | 观察默认排序与全部数据顺序 | 排序键与方向明确；同分组内方向一致；无"时间回跳"；默认排序优先业务发生时间而非记录创建时间（除非口径另有指定） |
| D2 | 筛选命中 | 逐个筛选条件单独验证 | 命中集与条件语义一致；状态类筛选不得跨状态混入其他状态的记录 |
| D3 | 清空筛选 | 清空全部筛选条件 | 刷新回全量列表 |
| D4 | 统计一致性 | 对比 tab 角标/统计数与实际条目数 | 完全相等；"今日/本周"等范围口径符合需求定义；状态统计覆盖全部状态（含异常态、超期态等易漏项） |
| D5 | 操作后刷新 | 执行保存/状态变更/编辑后返回列表 | 列表同步刷新，不展示过期数据 |
| D6 | 行与详情一致 | 对比列表行字段与点开详情 | 同名字段值一致；时间类字段跨页同源同值 |

## 五、状态流转与只读边界

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| E1 | 写操作触发流转 | 逐个执行写操作（暂存/提交/完结/撤销/作废） | 操作后的状态变化与状态机定义一致 |
| E2 | 重复操作边界 | 对已完结对象重复执行操作 | 阻止或按规则处理且给出结果反馈，不得静默无感知 |
| E3 | 跨页可见性 | 在 A 页操作后查看 B 页 | B 页列表状态/按钮态同步 |
| E4 | 只读边界 | 完结/归档/作废后逐入口检查 | 哪些只读、哪些可补录与口径一致；"可先完结后补录"类例外逐条验证 |
| E5 | 外部来源数据 | 操作缺少本地主键的外部系统记录 | 保存/完结链路可用（懒创建生效）；关键标识双空必须拒绝并有提示 |

## 七、操作反馈与防重复

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| G1 | 成功提示 | 执行保存/提交/新增 | 均有成功提示，文案指明结果对象 |
| G2 | 重复提示 | 重复创建同名/同号对象 | 有对应提示，不静默 |
| G3 | 失败提示 | 触发保存失败 | 失败原因友好可读，不裸抛堆栈/错误码 |
| G4 | 防重复提交 | 提交期间快速连点 | 按钮 loading/禁用，不产生重复数据 |
| G5 | 撤销/重置提示 | 点击撤销/重置 | 有确认提示 |
| G6 | 加载态 | 分别构造首次加载与刷新两种场景 | 有加载指示；加载中不以旧数据冒充新数据；不出现永久卡死 |
| G7 | 空态 | 分别构造「无任何数据」与「有数据但筛选无结果」 | 两种空态均有引导文案且可区分；不出现空白页或报错 |
| G8 | 错误态与慢态 | 断网/服务端报错/无权限/操作耗时过长 | 各自有明确提示与出口（重试/返回）；慢操作有进行中反馈；失败不产生半成品数据 |

## 十、需求对照（文档可用时才执行）

| 编号 | 检查点 | 动作 | 判定标准 |
|---|---|---|---|
| J1 | 控件类型逐一核对 | 逐控件对比文档 | 计数器 vs 数字输入框、输入+下拉组合 vs 纯输入、单选 vs 多选，类型一致 |
| J2 | 分版本表单逐版本走查 | 对按类别/版本区分的表单，每个版本单独跑一遍 | 差异内容（标题/文案/字段集合/分区结构）逐版本核对 |
| J3 | 文案逐字核对 | 对比标题、分区名、按钮名、提示语 | 与文档逐字一致；占位文案（lorem ipsum/演示数据/TODO）不得流入生产 |
| J4 | 排版还原 | 对比布局 | 对齐、区块顺序、高亮效果一致 |
| J5 | 展示完整性 | 检查下拉/文本区内容 | 不截断（注意视口高度与内容自适应） |
| J6 | 缺项申报 | 文档缺失/含糊时 | 能套用通用规则的按规则判；两边都无依据的列入"待确认清单"，不臆测 |
| J7 | 组件交互状态齐全性 | 逐组件检查 hover/focus/active/disabled 四态 | 文档有定义的逐一对齐；focus 态可见（去掉默认焦点样式必须有替代）；文字与背景对比度达标；文档未定义的走缺项申报 |

## 十二、测试数据构造要求

| 数据 | 支撑的检查点 |
|---|---|
| 覆盖每个分版本的合法业务对象 | J2、B8 |
| 边界值对象（值域下限/上限/超界） | A1-4、B5 |
| 缺失本地主键的外部来源记录 | E5 |
| 同对象多实例共存（A 已暂存 + B 待提交） | C 组 |
| 范围边界数据（"今日"前后各一） | D4 |

## 每轮收尾

新发现的缺陷模式回填本清单对应维度（新增检查点或细化判定标准），保持清单自增长。
