# UI 复刻与量化验收

> 正本位置：本仓库 `skills/engineering/design-to-code`。
> 来源：2026-11-26 同图同机对照实验——同一张 1672×941 后台图、同一台 Windows 机器、同一视口下，两版复刻直接对比（占位策略 8 轮迭代 SSIM 0.7446；切图策略 3 轮 SSIM 0.9453）。
> 核对日期：2026-11-26。适用范围：跨项目的「参考图 → 可维护 HTML/CSS 页面」。可信度：高（有同条件对照实验与区域级分项证据）。
> 用法：本 Skill 只约束复刻方法与验收口径；具体视觉规范以当前项目设计系统为准。

---

## 核心判断：上限由切图策略决定

同一实验的区域级证据（SSIM，越高越接近原图）：

| 区域 | 占位/线稿策略 | 真实切图策略 | 提升 |
|---|---:|---:|---:|
| 姿势卡 4 张角色图 | 0.4251 | 0.9901 | **+0.565** |
| Banner 角色插画 | 0.6966 | 1.0000 | **+0.303** |
| 侧栏品牌插画 | 0.9568 | 0.9548 | **−0.002** |

最后一行是决定性对照：**两版都切了图的区域分数几乎相同，没切图的区域差 0.3–0.57。**

归因：切图策略贡献 +0.15~0.20 SSIM（决定性），模型能力贡献 +0.03~0.05 SSIM（体现为自发量化验证、一次量准切片坐标）。**换更强模型不如先把切图做对。**

---

## 适用边界

适用：

- 有明确参考图（设计稿、AI 生成图、竞品截图）要复刻成可维护的 HTML/CSS；
- 需要客观判断两个复刻版本哪个更接近参考图；
- 复刻页面已存在，需要定位「哪里不像、该改什么」。

不适用：

- 没有参考图的自由设计；
- 整页原图当背景的静态 demo（还原度 100% 但不可用，本 Skill 的方法无意义）；
- 仅做视觉走查、不产出代码。

## 执行步骤

### 1. 先切图，再写码

动手写任何 HTML 之前，先把参考图里**所有非文字元素**切出存 `assets/`。

| 要切 | 不要切 |
|---|---|
| 角色、插画、头像、装饰图 | 卡片、圆角、阴影、渐变（用 CSS 画） |
| Banner 横幅整图（含手绘字标） | 图标（用 CSS `clip-path: path()` 描） |
| 姿势图、素材缩略图 | 纯色块、分割线 |

**硬规则：不许用占位图标或线稿近似。** 这是分数崩掉的第一原因。

切片脚本见 [scripts/prepare-assets.py](scripts/prepare-assets.py)，三个关键技巧：

1. **品牌区去字**：品牌名是文字，切进来会与 HTML 文字重影 → `cv2.inpaint` 抹掉；
2. **Banner 去正文**：用上下边缘颜色做线性渐变填充 + 边缘羽化；
3. **尺寸留余量**：比目测多切 2–4 px，用 `object-fit: cover` 裁掉，比切窄了露硬边好。

### 2. 写页面

代码只负责三件事：结构布局、图标形状、图表曲线。

- **布局**：纯 CSS flex/grid。**内联 style 控制在个位数**——实测 101 处内联样式会让全局调参（字重、间距）退化成逐个改，返工成本指数上升；
- **图标**：`clip-path: path()` 按参考图形状描。不手绘 SVG 近似（笔画永远对不上）、不用 emoji；
- **图表**：纯 CSS + `clip-path` 折线，比图表库更容易对齐参考图曲线；
- **字体**：系统栈 `"PingFang SC","Microsoft YaHei","Noto Sans SC",sans-serif`；
- **手绘字标**：直接切图，不要用系统字体近似。

### 3. 截图

与参考图同尺寸、同视口，无头浏览器截图：

```powershell
& 'C:\Program Files\Google\Chrome\Application\chrome.exe' --headless --disable-gpu `
  --hide-scrollbars --window-size=<W>,<H> --screenshot=<out.png> <url>
```

### 4. 量化验收

```bash
python scripts/replica_check.py --ref 参考图.png --shot 渲染.png \
  --ink "我的任务:283,598,365,626" --ink "角色数量:355,135,425,155"
```

输出：全图 SSIM、像素差异、8 区域分项、墨量（字重）体检、自动判读。支持多版本并排对比。
脚本见 [scripts/replica_check.py](scripts/replica_check.py)。

### 5. 迭代与停止条件

| 轮次 | 目标 |
|---|---|
| 第 1 轮 | 搭骨架 + 嵌入素材，所有区域 SSIM > 0.85 |
| 第 2 轮 | 修最弱区域（文字基线、素材错位、卡片配色） |
| 第 3 轮 | 墨量归零 + 微调数字/曲线/刻度 |

**停止条件**：3 轮后全图 0.94–0.95 且无区域 < 0.90 → 交付。

剩余 3–5% 是 AI 生成图的柔化边缘与亚像素抗锯齿，浏览器字体渲染追不上，属媒介差异。继续追是收益递减陷阱。

## 判读规则

| 信号 | 含义 | 动作 |
|---|---|---|
| 某区域 SSIM < 0.90 | 该块素材没切或错位 | **先查切图，别急着调 CSS** |
| 墨量差 > +1.5 个百分点 | 文字偏粗 | 去掉 `-webkit-text-stroke`，再降 `font-weight` |
| 墨量差 < −1.5 个百分点 | 文字偏细 | 查字号偏小、`letter-spacing` 过紧 |
| 全图 0.94–0.95 且无区域 < 0.90 | 已到该方法实际天花板 | 停手交付 |

**墨量**指文本区域内暗像素（`min(R,G,B) < 128`）占比。肉眼看不出的字重偏差一量就现形：实测偏粗 +5.6~+11.1 个百分点，归零后 SSIM 从 0.9319 升到 0.9453。这是比 SSIM 更快的定位手段。

## 常见坑（按踩坑频率）

| 坑 | 症状 | 解法 |
|---|---|---|
| 用占位/线稿代替素材 | 该区域 SSIM 0.4–0.7 | 切图，没有替代方案 |
| 用 `-webkit-text-stroke` 补清晰度 | 全图墨量偏粗 5–11% | 归零，改用字号/字距微调 |
| 只盯全图 SSIM | 修完涨不动，不知道修哪 | 看区域分项，找最弱那块 |
| 内联样式满屏 | 改一个字重要翻十几处 | 纯 CSS + 类选择器 |
| 手绘 SVG 图标 | 笔画永远对不上参考图 | `clip-path: path()` 按形状描 |
| 手写体用系统字体近似 | 字标笔画质感差 | 手绘字标直接切图 |
| 整页贴图冒充复刻 | 分数极高但页面不可维护 | 明确不属于本 Skill 的交付物 |

## 与其他 Skill 的边界

- 复刻完成后要系统性验收表单/列表/详情页的交互与业务规则 → `ai-test-checkpoints`；
- 复刻暴露出需要重新设计页面结构、影响高成本契约 → `task-design`；
- 只是调整已有页面的间距、颜色等小改动 → 直接做，不进本 Skill。

---

## 交付要求

1. 源码：`index.html` + `styles.css`（或等价拆分），素材在 `assets/`；
2. 最终截图与参考图同尺寸；
3. 量化报告：全图 SSIM、像素差异、区域分项、墨量对比（`replica_check.py` 输出）；
4. 如实说明剩余差异及其成因（哪些是媒介差异、哪些是取舍）。
