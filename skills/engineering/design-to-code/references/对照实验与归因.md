# 对照实验与归因（2026-11-26）

## 实验条件

| 项 | 值 |
|---|---|
| 参考图 | AI 生成的「公主孙悟空」后台首页，1672×941 |
| 渲染方式 | Windows Chrome 无头，`--window-size=1672,941` |
| 对比口径 | 同尺寸逐像素 SSIM（`skimage.metrics.structural_similarity`，`data_range=255`） |
| 像素差异 | 单通道最大差值 > 25 的像素占比 |
| 平均色差 | 全图 RGB 绝对差均值（MAE） |

两版由不同模型、不同策略产出，但在同一台机器、同一视口、同一参考图下渲染，条件可比。

## 全图结果

| 版本 | 策略 | 模型 | 迭代轮次 | SSIM | 像素差异 | MAE |
|---|---|---|---:|---:|---:|---:|
| 旧版 | 占位图标 + 线稿近似 | 猪八戒（前端） | 8 轮 | 0.7446 | 18.92% | 15.79 |
| Sol v1 | 真实切图 + 纯 CSS | gpt-6.2-sol high | 3 轮 | 0.9319 | 4.47% | 4.31 |
| Sol v2 | 同上 + 字重修正 | gpt-6.2-sol high | 3 轮 + 1 轮返工 | **0.9453** | **3.64%** | **3.59** |

注意：旧版迭代 8 轮仍在 0.74，Sol 版 3 轮即到 0.93。**方向错了，轮次再多也不收敛。**

## 区域分项（决定性证据）

| 区域 | 旧版 | Sol v2 | 提升 | 该区域是否切图 |
|---|---:|---:|---:|---|
| 姿势卡 4 张角色图 | 0.4251 | 0.9901 | **+0.565** | 旧版线稿占位 / 新版真实切片 |
| Banner 角色插画 | 0.6966 | 1.0000 | **+0.303** | 旧版渐变占位 / 新版整幅切片 |
| 纯文字 KPI 标签 | 0.5561 | 0.8803 | +0.324 | 都是代码文字，差异来自字重与字体渲染 |
| 纯 CSS 任务卡 | 0.6575 | 0.8746 | +0.217 | 都是代码，差异来自布局精度与字重 |
| 图表区 | 0.7576 | 0.9288 | +0.171 | 旧版 ECharts / 新版纯 CSS |
| 侧栏品牌插画 | 0.9568 | 0.9548 | **−0.002** | **两版都切了图** |

**结论**：都切图的区域分数几乎相同（差 0.002），没切图的区域差 0.3–0.57。切图是上限，其余是细节。

## 源码级差异

| 维度 | 旧版 | Sol 版 |
|---|---:|---:|
| 内联 `style` 属性 | 101 处 | 7 处 |
| `display:flex` / `display:grid` | 1 / 0 | 13 / 13 |
| 手绘 SVG 路径 | 67 处 | 0 |
| CSS 自定义属性 | 128 个 | 48 个 |
| 素材数 | 15 张（含 4 张占位） | 9 张（全部真实切片） |
| 图表实现 | ECharts 5.5 CDN | 纯 CSS + clip-path |
| 图标实现 | 手绘 SVG | `clip-path: path()` |

内联样式 101 处是旧版无法系统调参的结构性原因：改一个字重需要逐处修改，无法像 Sol 版那样在一条类选择器上调整。

## 字重（墨量）实验

墨量定义：文本区域内 `min(R,G,B) < 128` 的像素占比。

| 文本区域 | 参考图墨量 | Sol v1 墨量 | v1 偏差 | Sol v2 偏差 |
|---|---:|---:|---:|---:|
| 「我的任务」标题 | 29.18% | 38.24% | +9.06 | −0.91 |
| 任务 1 标题 | 10.25% | 15.88% | +5.63 | +0.52 |
| 「角色数量」标签 | 39.00% | 50.14% | +11.14 | +0.64 |
| 问候语 | 28.28% | 33.19% | +4.91 | −0.81 |
| 「首页看板」 | 15.62% | 19.60% | +3.98 | +1.17 |

根因是 `-webkit-text-stroke`（多处 0.16–0.32px）叠加 `font-weight:700/500`。全部归零后墨量回到 ±1.5 个百分点内，SSIM 从 0.9319 升到 0.9453。

**这条经验的价值**：字重偏差肉眼几乎无法判断，但用墨量一量就现形，且能直接指出改哪个属性。

## 归因结论

| 贡献项 | 约值 | 说明 |
|---|---:|---|
| 切图策略 | +0.15 ~ +0.20 SSIM | 决定性。给旧版同样切图，预计可达 0.88–0.90 |
| 模型能力 | +0.03 ~ +0.05 SSIM | 体现为自发量化验证、一次量准切片坐标、自动选用 clip-path |
| 字重修正 | +0.013 SSIM | 由量化驱动，不依赖模型强弱 |

**换更强模型不如先把切图做对。** 强模型的价值主要在省掉「教它怎么做」的提示词成本：Sol 版一次就自发做了量化验证，旧版 8 轮都靠主观「视觉验收通过」。

## 剩余差异的成因（为何停在 0.945）

1. **文字柔化边缘**：参考图是 AI 生成的抗锯齿文字，浏览器字体渲染无法逐像素复现，占剩余差异的大头；
2. **插画重采样**：切片在容器内 `object-fit` 缩放产生的重采样边缘；
3. **图标笔触**：线性图标与参考图手绘质感差异。

这三项属于媒介差异，不是代码缺陷。继续追是收益递减。
