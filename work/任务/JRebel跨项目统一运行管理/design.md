## 1. 背景、目标和边界

### 1.1 当前事实

维护源是 `skills/engineering/jrebel-start/`；各 Agent 的用户安装目录是分发副本。当前只有单项目启动规程和 `scripts/log-viewer/`，没有跨项目管理脚本。viewer 以工作目录为项目根，绑定本机 8199，不具备全局项目或进程账本。

设计时工作区已有 SKILL.md、viewer/index.html、viewer/server.mjs 三处未提交修改。本任务不得覆盖、回退或替换这些修改，不顺带重构 viewer。

### 1.2 目标

构建本机、Agent 驱动的跨项目 Java 应用运行管理能力：任意工作目录调用同一管理入口，可查看已注册应用，安全管理受支持的自有实例，查阅日志与运行证据。

- 多 Agent 共享本机数据；Skill 按各 Agent 的发现机制安装，不承诺所有工具天然共用一个安装目录。
- 第一版面向 Windows 11、PowerShell 7、Node.js 22；不安装 JDK，不引入第三方 Node 依赖。
- 默认不修改业务项目，不安装系统服务、数据库或常驻管理 Daemon。
- JRebel 的初始化、许可、插件、编译与热加载验证沿用现有规则，不把启动授权扩大为编译、测试、配置修改或批量操作授权。

### 1.3 阶段边界

| 阶段 | 范围 |
|---|---|
| P0，本次首版 | 限定目录发现；应用注册/更新/移除；跨目录列表；受支持启动方式的单实例启停；身份复核；并发互斥；中断恢复；实际监听端口；按批次日志；跨 Agent 会话管理 |
| P1，后续独立扩展 | 全机 Java 进程盘点与关联；主动 HTTP 就绪探针；JRebel 加载/许可诊断；实际热加载验证证据 |
| P2，不在本次 | 统一 Web 控制台；JVM 指标；同一应用多实例；远程机器管理 |

P0 返回就绪、JRebel 和热加载信息的结构化状态，但未实施检测的项明确为“未配置/未检测/未验证”，不能用进程存活冒充验证成功。现有 skill 可按用户要求额外采集证据，不将其伪装成管理器自动检测结果。

非目标：通用 IDE、通用非 Java 进程管理、Docker 编排、批量启停、自动构建、自动清日志、接管 IDEA 服务、修改已有机器上的业务服务。

## 2. 结构与职责

```text
各 Agent
  └─ SKILL.md：理解授权、阅读目标项目规则、发现与确认配置、解释结果
      └─ scripts/manager.mjs：稳定命令入口与确定性校验
          ├─ 注册表与运行记录
          ├─ Windows PowerShell 7 进程适配
          └─ 短期启动辅助进程：完成一次启动与记录后退出
              └─ 业务 JVM：独立于 Agent 和管理器会话运行
```

manager.mjs 是入口，不要求所有实现挤进一个文件；只在必要时拆分内部模块和固定 PowerShell 脚本。不得使用字符串拼接执行来自配置的 shell 代码；Windows 进程操作使用 pwsh，不使用 Windows PowerShell 5.1。

### 2.1 本机数据

默认 `~/.jrebel-start/`，由当前用户目录解析，不硬编码本机用户名。允许以全局参数 `--home <absolute-path>` 指定隔离数据目录，用于验证或独立配置；所有子进程必须继承同一解析结果。

```text
~/.jrebel-start/
├── projects.json
├── runtime/<appId>.json
├── logs/<appId>/<runId>.stdout.log
├── logs/<appId>/<runId>.stderr.log
└── locks/
```

- 配置和运行记录均带 schemaVersion；不支持的未来版本拒绝写入，不自动重建。
- 新安装的数据目录由当前用户持有；不宣称能隔离同一 Windows 用户下的恶意进程。
- 不写入 Skill 安装目录、业务项目或 Git 仓库。已有项目脚本日志只引用，不搬迁、不覆盖。
- 记录损坏时报错并保留原文件，不静默当成空注册表。重装或更新 Skill 不删除本机数据。
- 不建立额外数据库、常驻索引服务或历史状态数据库。按批次日志本身保留启动历史。

## 3. 应用注册与配置

### 3.1 核心对象

注册表以应用为管理单元。一个仓库可注册多个可启动应用，同一应用 P0 最多一份受管实例。

| 对象 | 核心字段和含义 |
|---|---|
| 应用 | 不可变 appId、可修改 alias、displayName、canonicalRoot、modulePath、启动描述、预期端口、配置 revision |
| 启动描述 | 模式、可执行文件、参数数组、cwd、非敏感选项、环境变量引用、配置来源文件与校验摘要 |
| 当前/最近运行记录 | appId、runId、operationId、配置 revision、启动阶段、PID、操作系统创建时间、可执行文件身份、预期命令指纹、日志路径、时间和最后操作结果 |

appId 和 runId 由管理器生成，仅含受限字符，不使用别名或未经处理的路径作文件名。唯一性是规范化真实仓库路径加应用定位；重复注册同一应用返回已有 appId，别名按 Windows 不区分大小写唯一。只接受明确项目根和应用入口，不以文件夹名称猜测入口。

### 3.2 发现和接入

- `discover --root <path> [--max-depth N]` 只扫描显式根；不默认扫描整块磁盘。跳过 .git、node_modules、target、build 及目录链接，设定深度/候选数量上限并报告截断。
- 扫描 Maven/Gradle 标记和本地启动线索，不执行构建工具、插件、wrapper、项目脚本或网络请求。
- 返回候选及证据；复杂继承、动态 Gradle 配置、多主类不能静态确定时返回未解析原因，不生成假完整配置。
- discover 不登记、不启动。register 只保存用户明确接入的应用；用户已指定单一项目并要求接入时，不再重复索取同一授权。
- 移除登记不是删除项目。身份确定仍在运行或状态未知时拒绝移除；应用停止后移除登记保留日志，不隐式停止实例。
- 不重复全目录扫描，但每次启动均检查目标路径、脚本/入口变化、JDK、编译产物、Agent/插件配置和已知端口冲突。失效配置必须报告，不能盲目照旧执行。
- 运行中禁止更换其启动描述；调整别名不影响 appId。配置更新使用 revision 检查，防止并发覆盖。

### 3.3 启动支持边界

**P0 可安全托管的基线是直接 JVM 启动**：使用明确 JDK 的 java.exe、参数数组、主类/classpath 或现成 JAR。不限定 Spring Boot，不强制项目改用 Maven/Gradle 启动。直接 JVM 可由已有项目说明与构建产物得到，不运行脚本去“试出”命令。

已有项目专用启动脚本仍是参数权威来源：优先引用；只有满足以下受管协议时才可自动启停，否则登记为只读/需原 skill 执行，并明确 `managedLifecycle=false`，不偷偷拆解执行或宣称已支持自动管理：

1. 能将本次 runId 以 JVM 系统属性 `-Djrebel.start.runId=<runId>` 传到目标应用，而非仅传给 Maven/Gradle 启动器。
2. 返回目标 JVM 的 PID、应用定位与日志路径；管理器再独立复核进程创建时间、可执行文件和 runId。
3. 不能同时启动多个业务 JVM、不可追踪的远端进程或产生超出授权的副作用。
4. 输出协议为明确机器可读结果；随意的控制台文案不构成可靠协议。

不为满足该协议自动修改现有脚本。任意 Maven/Gradle wrapper、IDEA 和后台脚本不是首版承诺的通用可托管入口。若仅能通过不兼容入口运行，start 在执行前返回 `UNSUPPORTED_LAUNCH`，保留原 skill 的项目启动能力，不造成半启动。

### 3.4 零侵入与凭据

默认不改 pom.xml、build.gradle、rebel.xml、源码、启动脚本及业务目录结构；不新增业务目录日志。缺少编译产物或 JRebel 监控配置时阻塞受管启动，说明缺项；构建或项目初始化需单独授权。

不得为兼容而自动移除 JRebel。用户明确选择普通 Java 启动时可登记为普通模式，状态明确显示未启用。

不保存密码、Token、许可证内容、带令牌的许可 URL。启动描述采用环境变量引用，执行时解析；缺失则阻塞。不得持久化展开后的秘密、完整环境或原始进程命令行。参数仅保留允许登记的非敏感内容，敏感选项要求引用，不声称启发式检查能证明任意字符串无秘密。

## 4. 命令契约

使用安装位置解析脚本绝对路径，不要求切换业务工作目录。默认输出简短人类可读结果，`--json` 输出稳定单一 JSON 对象；正常命令 stdout 不混入 PowerShell banner、应用日志或调试文本。

```text
node <skill>/scripts/manager.mjs discover --root <path>
node <skill>/scripts/manager.mjs register --config <file>
node <skill>/scripts/manager.mjs update <alias|appId> --config <file>
node <skill>/scripts/manager.mjs remove <alias|appId>
node <skill>/scripts/manager.mjs list
node <skill>/scripts/manager.mjs status [alias|appId]
node <skill>/scripts/manager.mjs start <alias|appId>
node <skill>/scripts/manager.mjs stop <alias|appId>
node <skill>/scripts/manager.mjs restart <alias|appId>
node <skill>/scripts/manager.mjs logs <alias|appId> [--run <runId>] [--stream stdout|stderr] [--lines N] [--follow]
```

- 所有命令仅作用于显式目标；stop/restart 不提供 all、通配符或按进程名称批量操作。
- list/status/logs 不启动、停止或修改业务文件。需要恢复运行记录时只在应用锁内更新本机账本。
- JSON 包含 schemaVersion、ok、command、data 或 error（code/message/可操作详情）；退出码区分成功、配置/参数错误、冲突、身份无法确认和执行失败。
- 日志输出限定已登记应用和受信启动记录中的路径，不接受任意路径读取。首次/普通读取限制字节和行数；follow 可中止，不把日志一次全读入内存。日志正文可能包含业务敏感信息，按用户明确查阅范围输出，不宣称自动脱敏。
- 自动化不启用交互提问；无法唯一确定时返回结构化问题，由 Agent 解释并向用户获取真正需要的决策。

## 5. 生命周期与证据

### 5.1 状态不混用

运行状态：STOPPED、STARTING、RUNNING、STOPPING、UNKNOWN。另有 lastOperation 记录失败原因；启动失败不必永久发明一个无法恢复的运行状态。

- RUNNING：身份匹配的目标进程当前存在，不等于业务就绪。
- STOPPED：已核实目标进程不存在；旧 PID 已复用为别的进程时不触碰新进程，并标注原实例已退出。
- UNKNOWN：权限不足、身份不全、启动恢复有歧义或查询失败；阻止 start/stop/restart 等可能重复启动或误停止的操作。
- 尚未启动过的已注册应用可显示 STOPPED（无受管实例），同时声明未盘点全部外部进程，不能解读成全机不存在该应用。

独立字段：expectedPorts（配置）、listeningPorts（进程实际监听）、readiness、jrebelAgent、license、hotReload。证据带 runId、observedAt、来源和原因；旧批次的结果不能使新实例变成健康或已验证。

### 5.2 启动与跨会话

1. 获取应用锁，检查配置 revision、已有受管实例、未完成操作及已知端口冲突。
2. 相同实例已运行则返回 alreadyRunning；UNKNOWN 或未完成启动意图未解决时拒绝再起。
3. 分配 runId、operationId，原子写入 STARTING 意图及日志定位，再启动短期辅助进程。
4. 辅助进程脱离 Agent 会话，使用确定参数启动业务 JVM，并将唯一 runId 注入系统属性；只允许一份符合身份的目标 JVM。辅助进程只覆盖本次启动事务，不长期驻留。
5. 取得 OS 创建时间、可执行文件与非敏感身份指纹，原子落运行记录；有限时间内确认进程未立即退出。生存确认只表示 RUNNING，不表示 readiness 通过。
6. 辅助进程完成后退出；业务 JVM 和日志写入不依赖管理器或 Agent 的 pipe/stdio。下一 Agent 会话可重读账本并实时复核。

管理器/辅助进程在各阶段异常退出时，保留启动意图。恢复以 appId、runId、可执行文件及创建时间范围查询：唯一且匹配可恢复；零候选且已证实启动辅助进程结束可记失败/停止；多个候选或辅助进程仍可能继续启动则 UNKNOWN，不能自动清账后重试。

申请启动必须在执行前确认当前运行器支持所选脱离方式；沙箱或宿主 Job Object 导致子进程随会话回收时如实报告不支持，不能声称已跨会话持久化。正式交付以真实会话退出验收为准。

### 5.3 安全停止与重启

- 停止只针对本机记录的自有实例；外部进程 P0 不接管，也不提供危险的 force-adopt 开关。
- 在应用锁内复核 PID、OS 创建时间、可执行文件和 runId。保存脱敏身份摘要/指纹，不保存完整命令行。
- Windows 停止适配必须对同一进程句柄完成创建时间核验与终止，避免“查 PID 后再按 PID 杀”之间的复用竞态。不能只按端口、主类或进程名停止。
- P0 stop 是有界强制终止已确认目标 JVM，不承诺 Spring/JVM shutdown hook 或优雅停机；Agent 执行前明确告知语义。无法取得可信身份/句柄则拒绝。优雅停机协议属于后续增强。
- 不使用 taskkill /T，也不盲目终止 Maven/Gradle Daemon、IDEA 或整个后代树。短期辅助进程不是待杀的业务服务。
- 等待目标确实退出；未退出则返回失败并保留记录。restart 在同一应用锁内先停再起，旧实例未退出禁止起新实例。
- 重复 stop 返回 alreadyStopped。移除注册表条目不替代停止流程。

## 6. 并发、异常和外部进程

注册表使用全局跨进程锁，运行操作使用 appId 级跨进程锁；统一顺序为应用锁→短期注册表锁，不在持有全局注册表锁时等待启动/停止。更新启动配置和移除应用也遵守同一顺序。不同应用启停互不串行。

- 锁通过排他创建取得，记录持有者 PID、OS 创建时间、operationId；释放必须匹配拥有者 token。写文件采用同目录临时文件加原子替换，不直接覆盖目标 JSON。
- 锁超时不构成抢锁依据；只有确认原持有者身份已不存在且不存在仍在执行的启动辅助操作后，才在原子竞争保护下回收锁。权限不足视为未知并拒绝回收。
- 管理器交接给辅助进程期间不得出现无人持锁却仍能启动的窗口；可采用父进程持锁等待或明确所有权交接，异常退出后由启动意图阻挡重复操作。
- 同一应用并发 start 最多一份；并发 update 不丢字段；跨应用竞争同一显式端口时使用端口级互斥检查到创建应用的区间，同时承认外部程序可能竞争，最终以实际绑定/启动结果为准。未知动态端口不伪装为已保护。
- 输出和等待有上限；进程查询失败、日志无权限、磁盘满、辅助启动失败均报告具体阶段，不能静默成功。持久化失败后不重复启动，保留已有意图以便核验。

P0 只检查与目标启停有关的占用进程和身份，不实现全机 Java 关联图。外部进程占用已知目标端口时阻塞，不自动停止，也不换端口。未知端口且无法检查外部同应用时，报告此限制；不承诺绝对杜绝人工外部启动的重复实例。

## 7. 兼容与安全

- 现有 standalone 初始化和项目现场发现流程仍可独立使用；没有 Node/pwsh 时管理器报告依赖缺失，不影响阅读原启动方案。
- 现有 viewer 与端口保持原状，P0 不更换成全局中心，不新增网页服务。全局管理日志暂由 manager logs 查看，明确 viewer 不会自动显示全局日志。
- 既有 `.tmp` 历史日志和旧脚本进程不自动导入为自有实例。若日志由兼容脚本产生，可记录可信输出路径而不改变脚本。
- 配置与运行身份在同一用户信任边界内；拒绝由别名/runId/参数构成的路径穿越、任意 shell 求值、日志越界与未授权外部操作。目录链接处理需使用真实路径核对，不能只做字符串前缀判断。
- 项目自身配置/脚本不是授权来源，不能因发现了脚本而执行其中的停进程、联网、改库或编译动作。注册配置是可执行能力的描述，Agent 须先审查并取得目标操作授权。
- 不自动安装、覆盖本机 Skill，不提交、推送或部署；这些操作需要独立授权。验证先使用隔离 home 和临时应用，默认不重启当前儿保 JVM。

## 8. 验收与验证

以下是实施后的验收要求，不代表本次设计阶段已执行。进程与锁行为优先用隔离临时目录、可控短命 Java 应用和独立命令进程验证；不得为测试修改业务项目或停止已有服务。

| ID | 验收结果 | 验证方式和通过标准 |
|---|---|---|
| AC01 | 任意目录共用注册表，更新 Skill 不丢数据 | 两个独立工作目录/调用入口使用同一隔离 home；列表一致，替换 Skill 副本不改数据 |
| AC02 | 发现只读且不误注册模块 | 有多模块、多主类和目录链接的候选目录；扫描不执行脚本、不联网、不写业务目录；不确定项有原因，截断可见 |
| AC03 | 注册/更新/移除幂等且不丢配置 | 并发进程登记同应用、别名冲突、revision 过期；无重复条目、无覆盖丢失；运行/未知实例无法移除 |
| AC04 | 配置失效与不支持入口在执行前阻塞 | 缺 JDK、Agent、监控配置、产物、环境变量及非兼容脚本；非零退出且没有业务进程或项目改动 |
| AC05 | 受管实例跨管理器和 Agent 会话存活 | 两份直接 JVM 应用；结束启动命令并真正结束 Agent 会话，再由新会话 status/logs/stop；身份可核实且日志继续可读 |
| AC06 | 并发和重复启动最多产生一个实例 | 同 appId 并发 start/重复 start/restart；仅一份唯一 runId 的目标 JVM，其他请求返回已有或明确冲突 |
| AC07 | 不误停其他或外部实例 | 两份自有应用和一份外部 Java；篡改/过期 PID、创建时间、runId及无权限案例；目标之外进程存活，身份不足拒绝停止 |
| AC08 | 停止和重启遵守强制终止语义 | 检查 Windows 同句柄核验与终止路径；实测已确认 JVM 退出；退出失败不启动新实例，不杀进程树 |
| AC09 | 中断后不产生重复或失联的可管理实例 | 在写意图、拉起辅助进程、创建 JVM、落记录阶段注入中断；唯一实例可恢复，歧义/仍启动中阻塞，无静默清账重起 |
| AC10 | 锁和损坏数据可安全处理 | 两命令竞争、持锁进程退出、活持有者超过超时、坏 JSON/未来版本；活锁不抢，死锁安全恢复，坏数据不清空 |
| AC11 | 状态有证据且不混淆 | 配置端口与实际端口不同、无 HTTP 探针、旧批次成功日志；分别展示预期/实际和未知状态，不伪报健康/热加载已验证 |
| AC12 | 日志和路径安全 | 多启动批次、stdout/stderr、大日志、follow、恶意 alias/runId/目录链接；读取有界，批次隔离，拒绝任意路径，无历史覆盖 |
| AC13 | 项目零默认修改、凭据不落账 | 对比临时业务目录前后文件清单/内容；运行记录/配置/普通输出不含展开的凭据或完整原始命令行 |
| AC14 | 既有能力不回退 | 对照现有 SKILL 和 viewer 行为；初始化/许可/构建授权不放宽，viewer 三处原改动保持，未自动迁移或停止现有服务 |

正式跨 Agent 兼容只对实际验证过的运行器作声明；Node 子进程实验不能替代 AC05 的真实 Agent 会话退出验收。未验证的运行器明确列为未验证，而非默认成功。

## 9. 确认项和取舍

### 阻塞确认项

无待补充的业务事实；以下作为当前 v1 的明确方案一起提交确认，不视为已获实施授权。

### 需要重点确认的方案取舍

1. 本次只交付 P0；Web、主动健康探针与自动 JRebel 诊断不混进首版。
2. P0 保证直接 JVM 和满足协议的脚本安全托管；不是任意 Maven/Gradle/IDEA 入口的通用接管器，不自动修改旧脚本。
3. P0 停止为经身份核验的强制终止，不承诺优雅停机；不允许接管外部实例。
4. “零侵入”指默认不改业务项目；缺编译产物/热加载配置时明确阻塞，不假装初始化成功。

### 非阻塞细节

命令输出排版、默认扫描上限、日志读取默认行数、模块拆分属于实施细节；不得改变本设计的授权、支持和身份边界。
